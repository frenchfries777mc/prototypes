# 루멘 와일즈 (가제)

3D로 렌더링해 픽셀아트처럼 보이게 만든 쿼터뷰 온라인 액션 RPG 샌드박스.
여러 플레이어가 하나의 절차적 생성 월드에서 채집하고, 몬스터를 사냥하고, 장비를 강화한다.

## 실행

처음이라면 아래 순서대로 한다.

1. [Node.js](https://nodejs.org) LTS 버전을 설치한다(22 이상).
2. 이 저장소를 내려받는다. GitHub 페이지의 **Code → Download ZIP** 으로 받아 압축을 풀면 된다.
3. 압축을 푼 폴더 안의 `lumen-wilds` 폴더에서 터미널을 연다
   (Windows: 폴더의 주소창에 `cmd` 를 입력하고 Enter).
4. 아래 명령을 한 줄씩 실행한다.

```bash
npm install
```

```bash
npm run build
```

```bash
npm start
```

5. 브라우저에서 http://localhost:8080 을 연다. 끝낼 때는 터미널에서 Ctrl+C 를 누른다.

개발할 때는 터미널 두 개로 `npm run dev:server` 와 `npm run dev:client` (http://localhost:5173) 를 띄운다.

| 명령 | 설명 |
| --- | --- |
| `npm test` | 단위·통합 테스트 (vitest) |
| `npm run typecheck` | 전체 타입 검사 |
| `npm run bots -- 200 ws://localhost:8080/ws 30` | 봇 200개로 30초간 부하 시험 |

환경 변수: `PORT`(기본 8080), `WORLD_SEED`, `DATA_FILE`(플레이어 저장 파일 경로).

조작: WASD/방향키 이동 · 마우스 왼쪽 또는 스페이스로 공격·채집 · 1/2/3 제작 · Enter 채팅.

## 구조

```
packages/shared   서버와 클라이언트가 함께 쓰는 결정적 로직
  world.ts        시드 기반 지형·자원 노드 생성 (전송하지 않고 양쪽에서 똑같이 계산)
  movement.ts     충돌 포함 이동. 클라이언트 예측과 서버 시뮬레이션이 같은 함수를 쓴다
  protocol.ts     바이너리 와이어 프로토콜 (인코더/디코더)
  content.ts      몬스터·아이템·제작법·성장 공식 (데이터 주도)
packages/server
  game.ts         권위 시뮬레이션: 입력 처리, 전투, 채집, 몬스터 AI, 관심 영역 스냅샷
  server.ts       HTTP + WebSocket 전송, 고정 틱 루프, 속도 제한
  store.ts        영속 계층 인터페이스와 파일 구현
  bots.ts         부하 시험용 봇
packages/client
  state.ts        클라이언트 예측·서버 보정, 원격 엔티티 보간
  render.ts       Three.js 렌더러 (저해상도 렌더 → 정수배 확대, 깊이 외곽선, 픽셀 격자 맞춤)
  models.ts       상자 조합으로 만든 캐릭터·몬스터 모델
  hud.ts          HUD, 이름표, 피해 숫자, 미니맵
```

## 핵심 설계 결정

- **서버 권위.** 클라이언트는 입력만 보낸다. 위치·피해·보상은 전부 서버가 계산하고,
  입력 예산·공격 대기 시간·메시지 속도 제한으로 조작된 클라이언트를 막는다.
- **20Hz 시뮬레이션, 10Hz 스냅샷.** 내 캐릭터는 같은 이동 코드로 즉시 예측하고 서버 확인(ack) 때 보정한다.
  다른 엔티티는 150ms 과거 시점으로 보간해 그린다.
- **관심 영역(AOI) + 델타.** 공간 격자로 주변 엔티티만 골라, 달라진 것만 보낸다.
  들어올 때(26)와 나갈 때(30)의 반경을 달리해 경계에서 깜빡이지 않는다.
- **지형은 전송하지 않는다.** 시드만 보내고 양쪽에서 같은 코드로 생성한다. 채집으로 바뀐 노드 상태만 청크 단위로 동기화한다.
- **3D 픽셀아트.** 실제 3D 장면을 약 270줄 높이의 버퍼에 직교 카메라로 그린 뒤 정수배로 확대한다.
  카메라를 픽셀 격자에 맞추고 남는 소수점 이동은 캔버스 위치로 보정해, 떨림 없이 부드럽게 스크롤된다.
  스프라이트를 직접 그리지 않아도 되고 조명·그림자·높낮이가 자연스럽게 나온다.

## 현재 한계와 다음 단계

- **규모.** 게임 서버는 단일 프로세스·단일 월드다. 4코어 장비에서 봇을 같은 장비로 돌린 최악의 경우(전원이 한 지점에 밀집)
  200명은 틱 평균 9ms, 600명은 43ms(예산 50ms)였다. 그 이상은 지역별 서버 분할(샤딩)과 경계 인계가 필요하다.
- **저장.** 플레이어 데이터는 JSON 파일 하나다. `Store` 인터페이스 뒤에 있으므로 데이터베이스 구현으로 교체하면 된다.
  고갈된 노드와 몬스터는 서버를 재시작하면 초기화된다.
- **계정.** 브라우저에 저장된 토큰이 곧 계정이다. 비밀번호·소셜 로그인은 없다.
- **콘텐츠.** 몬스터 3종, 자원 2종, 제작법 3종. 건설, 퀘스트, 파티, 거래, PvP, 사운드는 아직 없다.
- **몬스터 이동.** 길찾기 없이 목표를 향해 직진하며 벽을 따라 미끄러진다.
- **다른 플레이어의 레벨 표시**는 시야에 들어온 순간의 값이다.
