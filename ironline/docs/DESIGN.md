# Ironline 설계

## 목표

- 장르: 팀 기반 1인칭 거점 점령 슈터. 3v3 플레이어 + 팀당 최대 50명 봇.
- 시스템은 TumbleCrown(5v5, 순서대로 여는 거점)과 비슷하게 하되, **1인칭 시점 · 대규모 봇 · 무기 로드아웃 · 근대전 배경**으로 차별화.
- 그래픽: 복셀 모델 + 저해상도 렌더 + 정수배 확대 = 3D 픽셀. 병사는 키 1.85m = 34복셀이라 가까이서도 정교하다.
- 멀티플레이: 브라우저, PeerJS(WebRTC), 방장 권위. 별도 게임 서버 없음.

## 기존 게임과의 차이

| 항목 | Stickseum | SeumArena | TumbleCrown | Ironline |
|---|---|---|---|---|
| 시점 | 2D 횡스크롤 | 2D 탑다운 | 쿼터뷰 3D 픽셀 | **1인칭 3D 픽셀** |
| 캐릭터 | 영웅 33종 | 히어로 37종 | 직업 19종 | **무기 로드아웃 3종(영웅·스킬 없음)** |
| 목표 | 킬/점령 등 30모드 | 7모드 | 깃발 7개 순차 | 거점 5개 순차 + 병력(티켓) |
| 규모 | 2~16명 | 3v3~5v5 | 5v5~10v10 | **3v3 + 봇 최대 100명** |
| 배경 | 스틱맨 | 스틱피겨 | 중세 판타지 | 1914년경 가상 전선 |

## 구조 원칙

1. **시뮬레이션과 렌더 분리.** `Sim` 은 `RefCounted`, 노드·텍스처를 만지지 않는다. 헤드리스로 돌려 불변식과 성능을 테스트한다.
2. **물리 엔진 미사용.** 지형은 2m 높이 격자 쌍선형 보간, 소품은 AABB 목록 + 8m 공간 격자. 사람·봇이 같은 이동 함수를 쓴다.
3. **결정적 월드.** 시드만 보내면 모든 클라이언트가 같은 지형·소품을 만든다(전송하지 않음).
4. **고정 30Hz 틱 + 렌더 보간.** 시선(yaw/pitch)은 렌더 프레임마다 직접 적용하고 위치만 틱 사이를 보간한다.
5. **조명 계산 없음.** 면 방향 음영을 정점 색에 구워 언릿 머티리얼로 그린다. 웹·저사양에서 가볍고 도트 느낌이 일정하다.

## 성능 측정 (2026-11, 이 개발 환경)

| 대상 | 틱 평균 | 최악 |
|---|---|---|
| 네이티브 헤드리스, 80유닛 | 1.3ms | 7.0ms |
| 네이티브 헤드리스, 100유닛 | 1.7~1.8ms | 7~12ms |
| 웹(WASM, 소프트웨어 GL), 60유닛 생존 | 2~5ms | - |

예산은 33.3ms(30Hz). 웹은 네이티브의 약 3~5배. 방장은 렌더도 하므로 100유닛에서는 여유가 크지 않다 → 아래 최적화 과제.

## 로드맵

1. ✅ 시뮬레이션, 봇 AI, 순차 점령, HUD, 1인칭 렌더, 웹 내보내기.
2. **네트워크(PeerJS)**: 방 코드 생성/참가, 입력 전송, 스냅샷(AOI 델타), 클라이언트 예측, 빌드 버전 핸드셰이크.
3. **메뉴/로비**: 혼자 하기, 방 만들기, 코드로 참가, 팀·무기 선택.
4. **연출**: 피격 이펙트, 연기·폭발, 시체, 발소리/총성(절차적), 보행 애니메이션(다리 분리).
5. **성능**: 거리별 LOD(원거리 병사 저해상도 복셀), 봇 사고 주기 분산, 스냅샷 압축.
6. **콘텐츠**: 맵 추가, 수류탄/참호 도구, 점령 지점별 특수 규칙.

## 알려진 문제

- 봇 전투가 너무 대등해서 전선이 잘 움직이지 않는다(대부분 병력 소진으로 끝남). 돌격/방어 비율, 거점 압박, 병력 보급 규칙으로 조정 예정.
- MultiMesh 로 병사를 그리면 일부 GL 환경에서 보이지 않아, 현재는 유닛별 `MeshInstance3D` 를 쓴다(`?mm=1` 로 비교 가능).
- 웹 빌드에서 글꼴(Galmuri11 전체 글리프) 3.6MB. 필요한 글리프만 추리면 줄일 수 있다.
