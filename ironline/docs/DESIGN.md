# Ironline 설계

## 목표

- 장르: 팀 기반 1인칭 거점 점령 슈터. 3v3 플레이어 + 팀당 최대 50명 봇.
- 시스템은 TumbleCrown(5v5, 순서대로 여는 거점)과 비슷하게 하되, **1인칭 시점 · 대규모 봇 · 무기 로드아웃 · 근대전 배경**으로 차별화.
- 그래픽: 실시간 조명·그림자 풀 3D. 웹 내보내기 제약상 Godot 호환성 렌더러(WebGL2) 안에서 최대한 끌어올린다.
- 멀티플레이: 브라우저, PeerJS(WebRTC), 방장 권위. 별도 게임 서버 없음.

## 기존 게임과의 차이

| 항목 | Stickseum | SeumArena | TumbleCrown | Ironline |
|---|---|---|---|---|
| 시점 | 2D 횡스크롤 | 2D 탑다운 | 쿼터뷰 3D 픽셀 | **1인칭 풀 3D** |
| 캐릭터 | 영웅 33종 | 히어로 37종 | 직업 19종 | **무기 로드아웃 3종(영웅·스킬 없음)** |
| 목표 | 킬/점령 등 30모드 | 7모드 | 깃발 7개 순차 | 거점 5개 순차 + 병력(티켓) |
| 규모 | 2~16명 | 3v3~5v5 | 5v5~10v10 | **3v3 + 봇 최대 100명** |
| 배경 | 스틱맨 | 스틱피겨 | 중세 판타지 | 1914년경 가상 전선 |

## 구조 원칙

1. **시뮬레이션과 렌더 분리.** `Sim` 은 `RefCounted`, 노드·텍스처를 만지지 않는다. 헤드리스로 돌려 불변식과 성능을 테스트한다.
2. **물리 엔진 미사용.** 지형은 2m 높이 격자 쌍선형 보간, 소품은 AABB 목록 + 8m 공간 격자. 사람·봇이 같은 이동 함수를 쓴다.
3. **결정적 월드.** 시드만 보내면 모든 클라이언트가 같은 지형·소품을 만든다(전송하지 않음).
4. **고정 30Hz 틱 + 렌더 보간.** 시선(yaw/pitch)은 렌더 프레임마다 직접 적용하고 위치만 틱 사이를 보간한다.
5. **에셋 파일 없음.** 모델·텍스처·소리를 코드와 셰이더로 만든다(저장소가 가볍고 라이선스 걱정이 없다).

## 그래픽 구성

- 하늘: 셰이더(그라데이션 + 두 겹 FBM 구름 + 두 겹 산 능선 + 태양 코로나/글레어). 안개 색과 지평선 색을 맞춰 원경을 감춘다.
- 조명: 방향광 1개(PSSM 2분할 그림자, 120m), 색 앰비언트, 필름 톤매핑, 후처리(색보정·비네트·그레인·피격 효과).
- 지형: 2m 높이 격자 + 공동(cavity) AO + 낮은 곳의 물웅덩이(하늘 반사, 잔물결, 낮은 거칠기). 셰이더가 고도·경사·노이즈로 풀/마른 풀/흙/진흙/바위를 섞고 노이즈 법선으로 요철을 흉내 낸다.
- 풀: 청크별 정적 메시(블레이드 8장/다발)를 바람 셰이더로 흔든다. 78m 밖은 컬링, 품질 '낮음'에서는 끈다.
- 후처리(품질 단계별): 색수차·샤프닝·블룸(고리 샘플, 밉맵 미사용)·햇살 빛줄기(태양 방향 18탭 방사 블러)·S커브 색보정·비네트·그레인. 포격 연출(섬광·흙기둥·지연된 폭음·카메라 흔들림).
- 병사 셰이더: 올 무늬, 아래쪽 진흙 얼룩, 림 라이트.
- 전장 분위기: 타오르는 불(불꽃·불씨·깜빡이는 조명·연기), 카메라 주변 먼지 입자, 탄피, 1인칭 총구 섬광, 노리쇠 동작, 총알 스치는 소리, 발소리, 리버브.
- 소품: 정점 색 알파로 재질 종류를 넘기고 셰이더가 벽돌·포대 천·판자·나무껍질 무늬를 그린다. 48m 청크로 나눠 컬링한다.
- 병사: 15뼈 스켈레톤, 부위별 강체 스키닝(MeshInstance3D 1개 = 드로콜 1회). 타원 단면 곡면 몸통, 얼굴(눈·눈썹·코·입·콧수염·귀), 헬멧/군모, 탄띠·배낭·수통·삽·완장(팀 식별). 근거리 약 6.0k / 원거리(48m+) 약 1.9k 삼각형.
  70m 밖은 애니메이션 갱신 생략, 45m 밖은 그림자 생략, 150m 밖은 숨김.

## 성능 측정 (2026-11, 이 개발 환경)

| 대상 | 틱 평균 | 최악 |
|---|---|---|
| 네이티브 헤드리스, 80유닛 | 1.3ms | 7.0ms |
| 네이티브 헤드리스, 100유닛 | 1.7~1.8ms | 7~12ms |
| 웹(WASM, 소프트웨어 GL), 48~60유닛 생존 | 1~5ms | - |

삼각형 수: 지형 6.2만, 소품 19.4만(청크 53개로 분할), 병사 3.9k/1.5k(LOD).
이 개발 환경은 GPU 가 없어(소프트웨어 GL) 실제 프레임레이트는 측정하지 못했다. 실제 PC 브라우저에서 확인 필요.

예산은 33.3ms(30Hz). 웹은 네이티브의 약 3~5배. 방장은 렌더도 하므로 100유닛에서는 여유가 크지 않다 → 아래 최적화 과제.

## 로드맵

1. ✅ 시뮬레이션, 봇 AI, 순차 점령, HUD, 1인칭 렌더, 웹 내보내기.
2. ✅ **네트워크(PeerJS)**: 방 코드, 신뢰/비신뢰 채널 분리, 입력 12B + 스냅샷(15Hz, ≈12B/유닛), 클라이언트 예측·재적용 보정, 원격 유닛 보간, 빌드 버전 핸드셰이크, 중도 합류.
   남은 것: 방장 이탈 시 이전(지금은 판 종료), TURN 서버, 스냅샷 AOI·델타 압축, 지연 보상 사격.
3. ✅ **메뉴/로비**: 플레이, 방 만들기/참가, 대기실, 진영 선택, 그래픽·봇 수 설정.
4. **연출**: ✅ 예광탄·먼지·피·연기·총성·사망 자세 / 남은 것: 폭발, 발소리, 장전 애니메이션, 풀 덤불.
5. **성능**: 거리별 LOD(원거리 병사 저해상도 복셀), 봇 사고 주기 분산, 스냅샷 압축.
6. **콘텐츠**: 맵 추가, 수류탄/참호 도구, 점령 지점별 특수 규칙.

## 알려진 문제

- 봇 전투가 너무 대등해서 전선이 잘 움직이지 않는다(대부분 병력 소진으로 끝남). 돌격/방어 비율, 거점 압박, 병력 보급 규칙으로 조정 예정.
- 실제 GPU 에서의 프레임레이트 미측정. 느리면 `?q=1` 또는 `?q=0&scale=0.7`.
