# 대체역사 AI 시뮬레이션 — 설계 문서 v0.1

> 상태: 설계 단계 (코드 없음). 이 문서가 구현의 기준점이다.
> 가칭: **Althist** (이름은 나중에 정한다)

---

## 1. 목표와 범위

**한 줄 정의**: 플레이어가 한 국가를 골라 자연어로 명령을 내리면, LLM이 세계의 반응을 판정하고 지도 위의 영토·관계·사건이 갱신되는 턴제 대체역사 시뮬레이터.

**제약 (비용 0원 원칙)**
- 서버 없음. 정적 웹앱(GitHub Pages)으로 배포한다.
- 런타임 LLM은 (a) 사용자가 직접 입력한 Gemini 무료 API 키(BYOK), (b) 브라우저 내 Qwen(WebLLM) 두 가지만 쓴다.
- Claude(Max)는 **개발 단계 도구**로만 쓴다: 코드·프롬프트·데이터 매핑표 생성, 평가. 런타임에 호출하지 않는다.

**하지 않는 것 (v1 범위 밖)**
- 멀티플레이, 계정, 서버 저장
- 실시간 전투/전술 맵
- 이미지/음성 생성

## 2. 지도 정책 (확정)

| 지역 | 결정 | 표기 | 비고 |
|---|---|---|---|
| 대만 | **독립 국가 "Taiwan"**. 중국의 일부가 아니다. | `Taiwan` (※ "Chinese Taipei" 사용 안 함) | 본섬, 펑후, 진먼, 마쭈 포함 |
| 카슈미르 | **파키스탄령 부분만 파키스탄 소유**, 인도령은 인도 (해석은 아래) | — | 확정 |
| 크림반도 | **우크라이나 소유** | — | 크림 자치공화국 + 세바스토폴리 |

**카슈미르 해석 (확정)**
- **파키스탄 소유**: 아자드 카슈미르, 길기트-발티스탄 (파키스탄이 현재 실효지배하는 부분)
- **인도 소유**: 인도령 잠무·카슈미르, 라다크
- **중국 소유**: 악사이친 (현재 실효지배 유지)
- 즉 실효지배선(LoC) 기준의 현상 유지다. Natural Earth 기본 지도와 거의 같아서 오버라이드가 필요 없을 수 있다. 빌드 때 실제 폴리곤으로 확인한다.
- 의도와 다르면 오버라이드 표만 고치면 된다 (아래 구현 방식 참고).

**구현 방식: 데이터를 고치지 않고 "오버라이드 레이어"로 처리한다**
1. 원본 지도(Natural Earth admin-1)는 수정하지 않는다.
2. 빌드 스크립트가 `overrides/worldview.json`을 읽어 "주 ID → 시작 소유국"을 덮어쓴다.
3. 이 정책은 **시작 상태**일 뿐이다. 게임 안에서 플레이어와 AI가 소유권을 바꿀 수 있다.
4. Natural Earth는 일부 국가 관점(worldview)별 파일을 제공한다. 파키스탄·우크라이나 관점 파일이 있는지 확인해 참고 자료로 쓰되, 최종 기준은 우리 오버라이드 표다. (파일 존재 여부와 경계선 품질은 빌드 때 시각적으로 검증한다.)

```jsonc
// overrides/worldview.json (예시, ID는 빌드 시 실제 값으로 채운다)
{
  "name": "default-worldview",
  "rules": [
    { "match": { "country": "TWN" },                   "owner": "TWN", "displayName": "Taiwan" },
    { "match": { "adm1": ["<Crimea>", "<Sevastopol>"] }, "owner": "UKR" },
    { "match": { "adm1": ["<Azad-Kashmir>", "<Gilgit-Baltistan>"] }, "owner": "PAK" },
    { "match": { "adm1": ["<Jammu-Kashmir>", "<Ladakh>"] }, "owner": "IND" },
    { "match": { "adm1": ["<Aksai-Chin>"] },           "owner": "CHN" }
  ]
}
```

## 3. 핵심 설계 원칙

1. **LLM은 진실의 원천이 아니다.** 상태(지도, 소유권, 수치)는 코드가 소유하고, LLM은 "변경 제안(JSON)"만 낸다. 코드가 검증한 뒤 적용한다.
2. **소유(owner)와 실효지배(controller)를 분리한다.** 점령, 내전, 분쟁 지역을 표현하려면 처음부터 두 필드가 필요하다. 시작 상태에서는 둘이 같다.
3. **역할을 쪼갠다.** 해석 → 판정 → 서술 3단계. 작은 모델도 일부를 맡을 수 있다.
4. **재현 가능해야 한다.** 판정은 `seed`가 있는 RNG를 쓴다. 같은 저장 파일 + 같은 입력이면 같은 주사위가 나온다. (LLM 출력 자체는 비결정적이므로 응답을 로그에 저장한다.)
5. **제공자는 교체 가능하다.** `LLMProvider` 인터페이스 뒤에 Gemini, WebLLM, (선택) Claude API를 둔다.

## 4. 데이터 모델

```ts
type CountryId = string;   // "KOR", "TWN" ...
type ProvinceId = string;  // Natural Earth adm1_code 기반

interface Province {
  id: ProvinceId;
  name: string;
  iso: string;               // 현대 소속 ISO3 (참고용)
  owner: CountryId;          // 법적 소유
  controller: CountryId;     // 실효지배 (점령 시 owner와 다름)
  adj: ProvinceId[];         // 인접 그래프 (빌드 시 계산)
  centroid: [number, number];
  tags?: string[];           // "capital", "port", "strait" 등
}

interface Country {
  id: CountryId;
  name: string;
  color: string;
  leader: { name: string; title: string };
  government: string;        // "presidential republic" 등 (자유 텍스트 + 분류)
  stats: { stability: number; economy: number; military: number; influence: number }; // 0..100
  treasury: number;
  relations: Record<CountryId, number>;  // -100..100
  alliances: string[];       // alliance ids
  atWarWith: CountryId[];
  traits: string[];          // AI 성격: "isolationist", "expansionist" ...
}

interface WorldState {
  scenarioId: string;
  seed: number;
  date: string;              // ISO date
  turn: number;
  countries: Record<CountryId, Country>;
  provinces: Record<ProvinceId, Province>;
  treaties: Treaty[];
  log: TurnRecord[];         // 전체 기록 (저장용)
  memory: string;            // 롤링 요약 (프롬프트에 들어가는 압축 기억)
}

interface TurnRecord {
  turn: number;
  playerInput: string;
  actions: Action[];         // 해석기 출력
  diff: StateDiff;           // 검증을 통과해 적용된 변경
  headlines: string[];
  narrative: string;
}
```

**수치는 의도적으로 4개만 둔다** (안정, 경제, 군사, 영향력). 처음부터 늘리면 프롬프트와 균형이 무너진다. 필요하면 시나리오 단위로 확장한다.

## 5. 턴 파이프라인

```
플레이어 자연어 입력
   │
   ▼
[1] 해석기(Interpreter)      자연어 → Action[]   (규칙·ID 검증: 코드)
   │   소유하지 않은 것/존재하지 않는 ID → 코드가 거부하고 이유를 되돌려줌
   ▼
[2] 시뮬레이터(Simulator)    Action[] + 컨텍스트 → StateDiff 제안 + feasibility
   │   (플레이어 행동 결과 + AI 국가들의 반응 + 무작위 사건)
   ▼
[3] 엔진                    diff 스키마·규칙 검증 → RNG 판정 → 적용
   │   실패 시: 에러를 붙여 재시도 ≤2회, 그래도 실패하면 "변화 없음"
   ▼
[4] 연대기 작가(Chronicler)  확정된 diff → 헤드라인·서술
   ▼
[5] 메모리 압축             log 일부 → 500토큰 요약 (Qwen 담당 가능)
```

**모델 배정**

| 단계 | 기본 | 폴백 |
|---|---|---|
| 해석기 | Gemini Flash (구조화 출력) | Qwen (JSON 문법 제약) |
| 시뮬레이터 | Gemini Flash | 없음 (품질 하한 미달 시 경고 표시) |
| 연대기 작가 | Qwen | Gemini |
| 메모리 압축 | Qwen | Gemini |

### 컨텍스트 구성 (프롬프트에 넣는 것)
1. **정적 접두부** (항상 동일, 캐시 효과): 역할, 규칙, 시대 제약, 스키마, few-shot
2. **세계 요약**: 날짜, 활성 전쟁, 주요 동맹
3. **관련 국가 상세**: 플레이어국 + 인접국 + 교전국 + 동맹국만. 나머지는 한 줄 요약
4. **롤링 메모리** (≤500토큰)
5. **이번 턴 입력**

### 시뮬레이터 출력 스키마
```json
{
  "feasibility": 0,
  "reasoning": "한 문장",
  "events": [{ "type": "war_declared", "actor": "CountryId", "target": "CountryId" }],
  "province_transfers": [{ "province": "ProvinceId", "from": "CountryId", "to": "CountryId", "kind": "owner|controller" }],
  "relation_changes": [{ "a": "CountryId", "b": "CountryId", "delta": 0 }],
  "stat_changes": [{ "country": "CountryId", "stat": "stability|economy|military|influence", "delta": 0 }],
  "headlines": []
}
```
- `CountryId`, `ProvinceId`, `type`, `stat`는 **enum**으로 제한한다. 없는 ID를 지어낼 수 없다.
- 한 턴의 `province_transfers`는 상한(예: 5개)을 둔다. 급격한 변화를 규칙으로 막는다.

### 판정 규칙 (엔진, LLM이 아님)
- `feasibility`(0~100)와 시드 RNG 1회로 성패를 가른다: `roll < feasibility` → 성공 / 부분 / 실패 3단계.
- 영토 이전은 인접성(`adj`)과 전쟁 상태를 코드가 검사한다. 인접하지도 않고 교전 중도 아닌 주를 점령할 수 없다.
- 수치 변화량은 한 턴당 ±10으로 클램프한다.

### 시스템 프롬프트 원칙 (v0)
- 서사가 아니라 JSON만 출력한다.
- 현실성: 병참, 거리, 경제력, 국내 정치, 동맹 구조를 반영한다. **플레이어에게 유리하게 편향하지 않는다.**
- 시대 제약: 현재 날짜 이후의 기술·지식·사건은 쓰지 않는다.
- AI 국가는 각자의 이익, 성격(`traits`), 관계에 따라 **능동적으로** 행동한다.
- 한 턴에 일어날 법한 변화만 낸다.
- 불가능한 명령은 `feasibility`를 낮게 주고 이유를 `reasoning`에 쓴다 (거부하지 말고 결과로 처리).

## 6. UI 설계

```
┌──────────────────────────────────────────────────────────────┐
│ 2026-11 · 턴 14 · [Taiwan]            ⚙ 설정   💾 저장/불러오기 │
├───────────────────────────────────────┬──────────────────────┤
│                                       │  국가 패널            │
│                                       │  안정 ███░░  62       │
│            세계 지도                   │  경제 ████░  71       │
│     (소유국 색 · 호버 시 주 이름)       │  군사 ██░░░  38       │
│                                       │  영향력 ██░░░ 29      │
│        [레이어: 정치 | 관계 | 전쟁]     │  ──────────────      │
│                                       │  관계 · 동맹 · 전쟁   │
├───────────────────────────────────────┴──────────────────────┤
│ 연대기: 헤드라인 · 서술 (턴별 접기)                              │
├──────────────────────────────────────────────────────────────┤
│ > 명령을 입력하세요…                              [턴 진행 ▶] │
└──────────────────────────────────────────────────────────────┘
```

- 지도는 **정치 레이어**(소유국 색), **관계 레이어**(선택 국가 기준 호감도 그라데이션), **전쟁 레이어**(교전·점령) 3종.
- 주 클릭 → 소유국·실효지배국·태그 표시. 명령 입력창에 주 이름이 자동 삽입된다.
- 설정: 제공자 선택, Gemini 키 입력(localStorage 저장, 기기 밖으로 나가지 않음), Qwen 모델 다운로드 상태, 난이도(현실성 엄격도).
- 키 미입력 상태에서도 지도 탐색은 가능하다. LLM 필요 기능에만 안내를 띄운다.

## 7. 기술 스택

- **Vite + TypeScript**, 프레임워크는 최소화(필요 시 Preact/Solid)
- **지도**: MapLibre GL JS 우선 (줌·성능). 단순화 필요 시 D3-geo + Canvas로 대체 가능하도록 `MapView` 인터페이스로 격리
- **데이터 빌드**: Node 스크립트 `scripts/build-map.mjs` — Natural Earth admin-1 → mapshaper 단순화 → TopoJSON, 인접 그래프 계산, 오버라이드 적용
- **LLM**: `LLMProvider` 인터페이스 (`GeminiProvider`, `WebLLMProvider`)
- **저장**: localStorage + JSON 내보내기/가져오기
- **배포**: GitHub Pages

```
althistory/
  DESIGN.md
  src/
    engine/      # 상태, 검증, RNG, diff 적용 (순수 함수, LLM 비의존)
    llm/         # provider, 프롬프트, 스키마, 재시도 루프
    map/         # MapView, 레이어
    ui/
    scenarios/   # *.json (시작 상태, 매핑표)
  scripts/
    build-map.mjs
  data/
    raw/         # 원본 (수정 금지)
    overrides/   # worldview.json
  tests/
    golden/      # 프롬프트 회귀용 (명령, 기대 불변식)
```

**엔진을 LLM과 분리하는 이유**: 엔진은 순수 함수라서 LLM 없이 단위 테스트가 가능하다. 프롬프트가 바뀌어도 상태 무결성은 깨지지 않는다.

## 8. 시나리오 형식

```jsonc
{
  "id": "modern-2026",
  "name": "현대 (2026)",
  "startDate": "2026-01-01",
  "turnLength": "1 month",
  "worldview": "default-worldview",
  "countries": { /* 시작 국가 수치, 지도자, 성격 */ },
  "provinceOwners": { /* 오버라이드 외 예외 */ },
  "alliances": [],
  "playable": ["KOR", "TWN", "USA", "..."]
}
```
- 역사 시나리오(1914, 1936 등)는 `provinceOwners` 매핑표만 따로 만든다 (지도 기하는 공유). 초안은 Claude Code로 생성하고 사람이 검수한다.
- 현대 외 시나리오에서는 "카슈미르/대만/크림" 정책이 해당 시대 상황에 맞게 별도로 정의된다 (이 문서의 정책은 `modern-*` 시나리오 기본값).

## 9. 마일스톤

| 단계 | 산출물 | 완료 기준 |
|---|---|---|
| M0 지도 ✅ | 빌드 스크립트 + 정치 레이어 지도 | 세계 지도 렌더, 대만·크림·카슈미르가 정책대로 표시 — **완료 (아래 M0 결과)** |
| M1 엔진 ✅ | 상태/diff/검증/RNG | 완료 — 규칙 위반 제안은 거부, 난수는 시드 고정 |
| M2 LLM 연결 ✅ | Gemini BYOK 판정 | 완료 — 실제 키로 응답 품질은 미검증(모의 응답으로 파이프라인만 검증) |
| M3 루프 ✅ | 턴 진행, 세계 사건, 연대기, 저장/불러오기/되돌리기 | 완료 |
| M4 Qwen ⚠ | WebLLM 판정(실험) | 코드는 있으나 이 환경에는 WebGPU가 없어 **실행 미검증** |
| M5 품질 | 골든 테스트 30개, 프롬프트 튜닝 | 불변식 위반 0건 |

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| Gemini 무료 한도·정책 변경 | BYOK + 제공자 추상화, 호출 수 최소화(3단계 중 2단계는 로컬) |
| 작은 모델의 JSON/맥락 실패 | 문법 제약 디코딩, 재시도 루프, 시뮬레이터는 Qwen에 맡기지 않음 |
| LLM의 "항상 성공" 편향 | feasibility + 시드 RNG, 프롬프트에 편향 금지 명시, 골든 테스트 |
| 환각 ID/영토 | enum 스키마, 엔진 검증, 인접성 규칙 |
| 컨텍스트 폭증 | 관련 국가만 포함, 롤링 메모리 |
| 모바일 WebGPU 미지원 | Qwen은 선택 기능, 미지원 시 Gemini 폴백 |

- 영토 분쟁/비주권 단위(코소보, 소말릴란드, 북키프로스, 팔레스타인 등)는 Natural Earth 분류를 그대로 따라 별도 국가로 존재한다. 게임에서 어떻게 다룰지는 추후 결정 필요.

## 13. 플레이 가능 버전 구현 기록 (M1~M3)

**설계에서 바뀐 점**
- 3단계(해석→판정→서술) 대신 **한 번의 호출**로 합쳤다. 무료 한도(Gemini)를 아끼기 위함이다.
  한 호출이 `if_success` / `if_failure` / `world_events` 세 변경안을 한꺼번에 낸다.
- **성패는 LLM이 아니라 엔진이 정한다.** LLM은 `feasibility`(0~100)만 주고, 시드 난수 굴림이 `if_success`와 `if_failure` 중 무엇을 적용할지 정한다. (LLM이 항상 "성공"이라 답하는 편향 방지)
- **세 가지 판정 방식**이 같은 `Adjudication` 형식을 낸다: 규칙 모드(키워드, 키 불필요) / Gemini(BYOK) / WebLLM Qwen(실험).
- 도달 범위 그래프 `reach.json`: 육지로 맞닿거나 해협(약 1~2도) 건너 닿는 주. 점령/상륙은 이 범위 안에서만 가능하다(대만 해협 같은 해상 작전을 허용하면서 브라질 침공 같은 것은 막는다).
- 국가 초기 능력치는 Natural Earth의 인구·GDP·소득 구간에서 산출한다(핵보유국/취약국 보정 포함). 수작업 값이 아니라 근사치다.

**엔진 규칙(코드가 검증, LLM은 제안만)**
- 점령(`controller`): 상대와 전쟁 중이어야 하고 대상 주가 도달 범위 안이어야 한다(자기 영토 수복은 예외).
- 합병(`owner`): 이미 점령했거나, 소유국과 관계 +20 이상일 때만.
- 한 변경안당 영토 이전 최대 6곳, 능력치 ±10, 관계 ±40으로 제한. 모든 ID는 존재 여부를 검사한다.
- 영토를 전부 잃은 국가는 멸망 처리(플레이어면 게임 종료 안내).
- AI 출력은 HTML 이스케이프 후 표시한다.

**빈 땅 메우기(지도)**: admin-0에는 있으나 주 폴리곤에 덮이지 않은 조각 15개(올란드, 세우타·멜리야 등)를 가까운 주에 병합, 남극을 주인 없는 중립 영토로 추가, 마쭈·프라타스를 개략 도형으로 추가.

**검증**: `npm run build:single && npm run test:e2e` (Playwright 필요). 국가 선택 → 외교/전쟁/점령 → 되돌리기 → 저장 복원 → Gemini 모의 응답(코드펜스, 잘못된 ID/수치, HTML 주입, 429) → Qwen 미지원 환경 오류 → 모바일 레이아웃까지 자동으로 확인한다.

**아직 검증하지 못한 것(솔직한 한계)**
- **실제 Gemini 키로 호출한 적이 없다.** 이 환경에는 키가 없어서 응답을 흉내 낸 모의 서버로만 검증했다. 프롬프트 품질(판정의 현실성, JSON 준수율)은 실제로 돌려 보고 다듬어야 한다. 첫 응답이 형식 오류면 엔진이 오류 내용을 알려 주고 1회 재시도한다.
- **WebLLM Qwen**은 WebGPU가 있는 환경에서 실행해 보지 못했다(라이브러리 로딩과 오류 처리까지만 확인). 3B급 모델은 긴 JSON을 자주 틀릴 것으로 예상한다.
- 규칙 모드의 판정은 단순 키워드 기반이라 "자유로운 대체역사" 경험은 Gemini 모드에서 나온다.
- 영토 변경의 시각화는 점령(점선 테두리)과 소유 이전까지만 있다. 새 국가 탄생(분리독립, 건국)은 아직 없다.
- 시작 시 전쟁은 없다(전부 평시). 현실의 분쟁은 AI가 알고 있는 지식에 맡긴다.

**시작 흐름(최종)**: ① 흰 배경 시작 화면에서 템플릿과 AI 판정 방식 선택 → ② 지도에서 나라를 직접 클릭(왼쪽 카드에 능력치 표시, 검색창/드롭다운 없음) → ③ 플레이.
- 템플릿은 `data/scenario/*.json` 한 파일이 한 템플릿이다(동맹, 초기 관계). 지도 기하는 공유한다. 현재: 현대 2026, 양극 냉전 세계, 백지 세계.
- 역사 시대(1914/1936/1444)는 그 시대의 주 소유 매핑표가 필요해서 "준비 중"으로 표시만 한다.
- 화면의 국가/지명은 한국어 이름만 쓴다(영어 병기 없음). 한국어 이름이 없으면 영어로 대체한다.

## 14. 역사 템플릿 19종 (구현 기록)

지도는 현대 행정구역(주 3,549개) 하나뿐이다. 역사 시나리오는 **시나리오 전용 국가 목록**(로마, 카르타고, 조선, 프로이센 …)과 **"현대 주 → 당시 소유국" 칠하기 규칙**(`data/history/*.mjs`)으로 만든다.

- 규칙은 `국가 코드 / 좌표 상자(주 중심점) / 주 이름` 선택자이며, **나중에 칠한 것이 앞의 것을 덮어쓴다.** 규칙이 주를 하나도 못 잡거나 국가 코드가 틀리면 빌드가 경고한다.
- 남은 땅: 고대~근세는 `기타 세력`(주인 없는 땅, 선전포고 없이 개척/정복 가능), 1900년대 이후는 현대 국가를 축소 능력치의 독립국으로 그대로 쓴다.
- 시나리오마다 시작 날짜(기원전 지원), **턴 길이**(1~12개월), 시작 시 진행 중인 전쟁, 초기 관계/동맹, 브리핑·GM 지침(AI에게 전달), 군대·장군, 병력 보정(`milMod`)·키워드 보너스를 가진다. 임진왜란은 "이순신 사기, 명 장수 무능"을 이 보정과 GM 지침으로 구현했다.
- **지도의 한계**: 국경은 현대 행정구역에 맞춘 근사이므로 옛 국경과 정확히 일치하지 않는다(특히 고대·중세). 소국/도시국가는 합쳐서 표현했다. 크림 전쟁에서 크림은 러시아 영토다(현대 정책과 별개로 역사적 사실에 맞춤).

## 15. 장군과 군대

- 상태: `Army {id, name, owner, general{name, skill 1~10, trait, status}, troops(천 명), morale, at, navy}`. 새 게임/옛 저장 파일은 `buildArmies()`가 만든다: 템플릿의 명시 군대 + 나머지 나라는 군사력·시대 배율로 자동 생성(전선 주 우선 배치).
- 엔진 규칙(`diff.ts`): `army_moves`(한 턴 이동 거리 제한, 전쟁 중이 아닌 나라 땅 통과 금지), `army_changes`(병력 하한/상한, 사기, 장군의 부상·포로·전사 → 부장 승계, `불패`는 면제), `army_new`(한 번에 2개, 자국 지배 주에서만). **점령은 해당 주 또는 인접 주에 아군 군대가 있어야 하고 적 방어군이 남아 있으면 거부**된다.
- 규칙 모드: 장군/군대 이름으로 군대를 고르고, 병력·장군 능력·사기·지형 보정에서 전투 확률을 계산한다(해전은 함대끼리). LLM 모드: 프롬프트에 `ARMIES` 목록(내 군대 전부 + 교전국/근처 군대)과 규칙을 넣고, AI가 군대 ID로 이동·전투 결과를 제안하면 엔진이 검증한다.

## 16. 템플릿 스튜디오와 공유

- 스튜디오(`src/studio/Studio.ts`): 지도에 칠하기, 국가/능력치, 관계·전쟁, 군대·장군(위치는 지도에서 지정), 검증, 테스트 플레이, 내 템플릿 저장(localStorage), 파일 내보내기, 공유.
- 템플릿 형식 = 런타임 시나리오 형식(`schema: 1`, `owners`는 주 순서의 국가 인덱스). **외부에서 온 템플릿은 모두 `sanitizeScenario()`로 다시 검증한다**: 길이 제한, 색상은 `#rrggbb`만, ID 정규식, 수치 범위 클램프, 정규식/코드는 받지 않음(키워드 목록만), 지도와 주 개수가 맞는지 확인.
- 공유: GitHub 저장소의 폴더(`shared-templates/`)가 갤러리. 읽기는 공개 raw URL, 올리기는 사용자의 토큰으로 GitHub Contents API(템플릿 파일 + `index.json`). 토큰은 저장하지 않는다.

## 17. 검증하지 못한 것 (이번 작업)

- **GitHub 업로드와 갤러리는 모의 서버로만 검증**했다. 실제 토큰/저장소로는 호출해 본 적이 없다(이 환경에 토큰과 GitHub API 접근이 없다). 요청 순서(파일 확인 → PUT → index.json 확인 → PUT)와 오류 처리는 테스트했지만 실제 응답 형식 차이가 있을 수 있다. 기본 갤러리 주소는 `main` 브랜치라 병합 전에는 비어 있다.
- **실제 Gemini 키로 군대·전투 판정을 해 본 적이 없다.** 프롬프트의 군대 규칙이 모델에서 얼마나 잘 지켜지는지는 직접 돌려 보며 다듬어야 한다. (엔진이 잘못된 제안은 거부하므로 상태가 깨지지는 않는다.)
- 역사 템플릿의 **인물·병력 수치는 대략적인 근사**다(고증 검수를 거치지 않음). 국경도 현대 행정구역 기준 근사다. "적당히" 수준의 재현이다.
- 규칙 모드(키워드)의 전투는 단순하다. 지형·보급·포위 같은 요소는 LLM 모드에서 서술로만 반영된다.
- 스튜디오는 데스크톱 화면 기준으로 다듬었고 모바일에서는 사용이 불편할 수 있다.

## 18. AI 선택과 시각화된 템플릿 화면

- "판정 방식(모드)" 선택을 없애고 **AI 선택**(Gemini / Claude / Qwen)만 남겼다. 규칙 기반 판정은 선택지가 아니라, 고른 AI에 키가 없을 때 엔진이 대신 쓰는 **간이 판정**이다(화면 상단에 "간이 판정 (AI 키 없음)"으로 표시).
- **Claude**: 공식 TypeScript SDK(`@anthropic-ai/sdk`)로 브라우저에서 사용자 API 키를 써서 직접 호출한다(`dangerouslyAllowBrowser`). 기본 모델 `claude-opus-5-5`, `effort: medium`, 거절 시 서버 측 대체(`fallbacks: "default"`). Claude 구독(Max 등)과는 별도로 API 사용량만큼 과금된다. **실제 키로는 호출해 보지 못했고**, 요청 형식과 오류 처리(401 등)는 모의 서버로 검증했다.
- **템플릿 카드**: 각 템플릿의 시작 정치 지도를 캔버스로 그린 썸네일(전체 22개 약 0.3초, 캐시), 연도·"전쟁 중" 배지, 주인공 국가(전쟁 당사국 → 군대 보유국 → 영토 순). 선택한 템플릿은 위쪽 큰 미리보기에 설명·주요 국가·시작 전쟁·이름난 장군을 보여 준다. 시대별 필터 칩.

## 19. 빈 땅 채우기(fill)와 작은 주 합치기

**빈 땅 채우기.** 역사 템플릿(`data/history/NN-*.mjs`)이 칠하지 않은 땅은 `data/history/fill/<템플릿 id>.mjs`가 그 연도에 실제로 있던
나라·왕국·민족·문화로 채운다(시대별 공용 모듈 `_ancient`, `_early-medieval`, `_late-medieval`, `_c1600`, `_c1700`, `_w19fill`, `_w20fill`, `_wpostfill`).
채우기는 "아직 빈 땅"에만 칠하므로 템플릿이 직접 칠한 곳은 바뀌지 않는다. 템플릿 쪽에서 칠한 땅이 틀렸으면 템플릿에서 그 줄을 빼면 채우기가 이어받는다
(예: 1618~1756년 템플릿은 라틴아메리카·인도네시아를 칠하지 않고 채우기가 부왕령·술탄국으로 나눈다). 사람이 살지 않던 땅만 `무인지`(고를 수 없음, 군대로 개척 가능)로 남는다.
형식과 선택자는 `data/history/fill/README.md`. 검사: `HIST_DRY=1 HIST_ONLY=<id> HIST_GAPS=1 node scripts/build-map.mjs` (파일을 쓰지 않아 동시에 여러 개 돌려도 된다).

**작은 주 합치기.** 원본이 시·군 단위인 나라(슬로베니아 193개, 몰타 68개, 영국 232개 …)는 지도에서 주가 점처럼 작다.
`build-map.mjs`는 주 면적의 중앙값이 700km² 미만인 나라에서만 1,500km² 미만 주를 공유 경계가 가장 긴 이웃에 합친다(서울·부산처럼 특별시가 작을 뿐인 나라는 대상 아님).
육지 이웃이 없는 섬은 8도 안의 같은 처지의 섬끼리만 합친다. 합친 주는 가장 큰 구성원의 id·영문 이름을 쓰고 한국어 이름에 "일대"를 붙인다.
`-dissolve`는 합쳐지는 묶음에만 적용한다(전체에 적용하면 비르 타윌 같은 특이한 주의 모양이 사라진다).

**호버·선택 테두리.** `setFilter`는 주 4천여 개 레이어의 타일을 다시 계산해 커서보다 늦게 따라온다. 호버(하양)·선택(노랑) 테두리는 `feature-state`로 켜서 즉시 반영한다.

## 20. 큰 주 쪼개기와 자잘한 나라 합치기

**주 쪼개기.** 원본 admin-1 에서 한 주가 여러 역사 지역을 담는 곳은 `build-map.mjs` 의 `SPLITS` 로 상자(box)를 따라 잘라 나눈다(mapshaper `-clip bbox`/`-erase bbox`).
지금은 바이에른(DEU-1591)을 오버바이에른·니더바이에른·오버팔츠·프랑켄·슈바벤 5개로 나눠, 선제후국 바이에른이 영토 3개를 갖고 프랑켄·슈바벤은 별개 주교령이 된다. 잘린 선은 직선이라 실제 경계와는 다르다.

**자잘한 나라 합치기.** 채우기로 만든 나라 중 땅이 작은 것(아프리카 해안의 소왕국, 북미·아시아 부족 …)은 땅이 맞닿은 채움 나라 가운데 가장 긴 경계를 가진 나라에 합친다
(`mergeFragments`: 면적 20만km² 미만, 합친 뒤 70만km² 이하). 우랄 동쪽 러시아(시베리아)는 180만km² 미만을 합쳐 더 큼직하게 묶는다(합친 뒤 380만km² 이하). 작은 쪽이 칸국·왕국처럼 국가다운 이름이고 큰 쪽이 부족 이름이면 국가 이름으로 합친다.
유럽은 합치지 않는다(독일·이탈리아의 작은 나라는 일부러 나눈 것). 합쳐진 나라의 이름은 큰 쪽을 따르고 작은 쪽 이름은 명령어 인식용 별칭으로 남는다.

## 21. 세력 AI·호외·외교 반응·명령 자동 완성

**세력 AI**(`src/engine/ai.ts`, 규칙 기반·시드 난수라 결정적). 플레이어 명령 처리 뒤 매 턴: ① 국경을 맞댄 나라끼리 **관계가 -35 이하**이고 힘이 앞서면 선전포고
(확률은 점수 × 난이도 배율: 쉬움 .35 · 보통 1 · 어려움 1.7 · 지옥 2.6, 한 나라 동시에 2개 전쟁까지, 한 턴 1~2건) ② 플레이어와 무관한 전쟁은 턴마다 5% 휴전
③ 내가 이번 턴에 시작한 전쟁에는 상대의 우방(관계 40↑)이 비난(관계 -8), 나의 우방이 지지(+5). 군대 이동·점령은 하지 않는다. 결과는 `TurnRecord.diplo`(신문 외교 소식 맨 앞).
**호외**: `TurnRecord.alert` — 내가 전쟁을 시작했거나, AI가 나에게 선전포고했거나, 멸망·영토 2곳 이상 상실·3곳 이상 획득이면 신문에 붉은 "호 외" 띠.
**명령 자동 완성**: 명령창 입력 끝의 글자로 나라 이름·별칭과 내 군대 이름(띄어쓰기 포함 앞부분 일치)을 후보로 띄우고 Tab/↑↓/클릭으로 채운다.

## 22. 군대 AI와 숨은 안정도

- `src/engine/aiwar.ts`: 전쟁 중인 AI 나라의 군대가 턴마다 이동 범위(`moveHops`) 안의 적 영토를 골라 진군한다. 방어군이 없으면 점령, 있으면 전투력(`armyPower`)×방어 이점 1.2로 확률 판정(`winChance`, 시드 난수)한다. 질 싸움(승률 45% 미만)은 걸지 않는다. 승자는 땅을 차지하고, 패잔병은 아군 땅으로 후퇴하거나 흩어진다. 난이도가 높을수록 한 나라가 한 턴에 움직이는 군대가 많다. 플레이어의 군대는 움직이지 않지만 공격받으면 방어한다.
- `src/engine/stability.ts`: 안정도(`stats.stability`)는 UI·신문에 나오지 않는 숨은 변수다(`SHOWN_STATS`는 경제·군사·영향력만). 매 턴 목표치(경제·영향력↑, 전쟁↓)로 서서히 수렴하며 점령당하면 떨어진다.
  - 50 기준 ±10%p로 플레이어 명령의 성공 확률에 더해진다(`supportBonus`).
  - 35 미만이면 소요·파업(경제 감소), 20 미만이면 폭동/반란. 시나리오에 "주인 없는 땅" 세력이 있으면 영토 한 곳이 반란군 손에 넘어간다.
  - 60 이상이면 가끔 국민 결집으로 군사력이 오른다.
- 점령·반란·전투 결과는 모두 신문(외교 소식)에 기사로만 실리고, 플레이어가 공격받거나 땅을 잃으면 호외가 나온다.

## 23. 목표·결말, 사실 기록부, 모델별 프롬프트

- **목표(`engine/goals.ts`)**: 플레이어 나라 기준으로 4개 자동 생성(영토 +25%, 경제 +15, 영향력 +15, 생존 N턴; 기준은 처음 화면을 그린 시점). 3개를 이루면 승리 결말. 멸망하거나, 숨은 안정도가 15 이하로 4턴 쌓이면(40 이상 회복해야 초기화) 정권 붕괴로 패배 결말. 결말은 한 번만 나고, 신문을 닫으면 결말 창이 뜨며 계속 플레이할 수 있다.
- **사실 기록부(`engine/memory.ts`)**: 엔진이 확인한 사건(전쟁 개시·종결, 영토 증감, 관계 급변, 반란, 목표)을 최근 30줄 `ledger`에 적고 누계 `tally`를 센다. 프롬프트의 `LEDGER`로 들어가 모델 품질과 무관하게 서술의 기준이 된다. AI가 쓰는 `memory`(NOTES)는 약속·진행 중 계획·인물·미해결 위기만, 날짜를 붙여 12줄·중복 제거로 둔다.
- **모델 프로필(`llm/profile.ts`)**: 모델 이름으로 strong/mid/small/tiny를 가늠해 시작 프롬프트 단계, 온도, 지침, 예시 여부를 정한다. 작은 모델(≤14B, lite/nano/gemma 등)은 간추린 프롬프트 + 예시 + 짧은 지침 + 낮은 온도, 3B 이하는 더 짧게. 이름으로 알 수 없으면 mid(전체 프롬프트).

## 24. 지도 크기 정규화 (`scripts/build-map.mjs`)

원본(Natural Earth admin-1)은 나라마다 쪼개진 정도가 달라 주 크기가 제각각(이탈리아 중앙값 2,400㎢, 독일 18,000㎢, 스위스 칸톤은 6㎢도 있음)이었다. 빌드 때 아래 순서로 고른다.

1. **큰 주 쪼개기** (`splitBig`): 유럽(경도 -12~40, 위도 35~61)은 15,000㎢, 그 밖은 150,000㎢를 넘는 주(상한의 1.25배 초과)를 면적 가중 k-평균으로 씨앗을 정해 보로노이 칸으로 나눈다(`polygon-clipping`으로 교차). 자르는 선은 칸의 변을 잘게 나누고 매끄러운 변위장(사인파 2겹)으로 굽혀 자연스럽게 만든다. 변의 점은 끝점 순서를 정해 만들고 좌표를 1e-6도로 맞춰서 이웃 조각이 같은 선을 공유한다(틈·겹침 없음). 바깥 경계는 원본 꼭짓점을 그대로 지켜 이웃과 틈이 없다. 이름은 원래 이름 + 방위(북·남동·중부), id는 `원래id-s2`. 바이에른 5개 지방은 지방 중심 도시 좌표를 씨앗으로 쓴다(직사각형 자르기 폐지).
2. **작은 주 합치기** (`mergeOversplit`): 같은 나라·같은 소유국 안에서만. 기준은 나라 중앙값에 따라 1,500㎢(시·군 단위로 잘게 쪼개진 나라) / 4,000㎢(중앙값 4,000㎢ 미만) / 400㎢(나머지). 경계 90% 이상을 이웃 하나와 맞댄 **비지**(베를린·브레멘·울란바토르 …)는 크기와 상관없이 둘러싼 주에 합친다. 별개 나라(바티칸·산마리노·레소토 …)는 소유국이 달라 그대로 남는다.
3. **템플릿 보호**: 모든 역사 템플릿의 이름·좌표 상자 선택자를 미리 모아, 선택자 집합이 같은 주끼리만 합친다(템플릿이 가르는 경계는 합치지 않는다). 합쳐지거나 쪼개진 주의 id는 `idAlias`로 `ids` 선택자가 따라가고, 쪼개진 조각은 좌표 상자 판정에 원래 주의 중심을 쓴다.

결과: 주 3,609 → 3,549개, 중앙값 5,755 → 10,560㎢, 하위 10% 608 → 1,641㎢. 저장해 둔 사용자 템플릿이 합쳐지거나 쪼개진 주 id를 직접 가리키면 어긋날 수 있다.

## 25. 키 없는 무료 AI 번갈아 쓰기 (`llm/providers.ts`)

키 없이 쓰는 서비스(`rotate: true`: Pollinations, LLM7)는 한 묶음으로 번갈아 쓴다. 요청 직전 `pace()`가 지금 쓸 수 있는 서비스(간격이 지났고 한도 쉬는 중이 아님)를 고르고, 없으면 가장 빨리 풀리는 쪽만 기다린다. 한도(429·"Retry after")에 걸리면 그 서비스를 `coolUntil`로 쉬게 하고 기다리지 않고 다른 서비스로 바로 넘어간다(프롬프트 길이 한도·모델 프로필도 서비스에 맞춰 다시 맞춘다). 사용자가 키를 넣은 서비스는 번갈아 쓰기에서 빠진다. LLM7은 키 입력칸이 비어 있어도 형식상 `Bearer unused`를 보낸다. 모델 목록은 유료(pro) 등급을 빼고 보여 준다. LLM7의 실제 무료 한도는 확인하지 못했다(조사 시점에 무료 토큰 한도 소진 응답 `retry in 3600 seconds`를 받음).
